## 0. 这份文档怎么用（写给以后接手的人 / 写给以后的我）

1. **改任何一个脚本，必须同步改本文三处**：对应站点章节、§8 版本与交付表、附录源码块。版本号 `@version` 要递增，并把新链接补进交付表（旧链接保留，标"已废弃"，方便回溯）。
2. **改之前先看 §9 已知问题**，别把已经踩过的坑再踩一遍。
3. **交付流程固定**：`node --check` 过 → 上传 CDN → `curl -r 0-40` 验 206 → 给安装链接。别拿没验过的链接让用户装。
4. **设计红线**（用户明确否决过，不要违反）：不做会拖卡浏览器的东西（尤其弹窗清理不许用 MutationObserver + 全量 innerText 扫描）；不动 `remove()` 删站点弹层（会让 React 抛 `insertBefore` 错）；面板不要写死"检测中…"占位；不要固定回复套话；不索要联系方式、不谈钱、不开黄腔、不 PUA。
5. 四份源码在 §10 / §12 附录，**以附录为准**；万一仓库里的文件被覆盖，用附录内容重建。

## 2. 通用设计（三站一致的部分）

### 2.1 人设：具体到能被追问的男生，不是"暖男模板"

系统提示词结构固定为五块，三站只有年龄/城市微调（星缘 21 岁福州、缘起与 nvda 20 岁北京）：

- **【你是谁】**：写代码的、会做番茄牛腩、周末骑车爬山、爱看老电影、方向感差、偶尔熬夜。**必须有可被追问的具体细节**——这是"像人"的地基，模板人设一追问就崩。
- **【关系阶段】**：四段，脚本每轮告诉模型当前在哪段，只做该段的事。
  1. 陌生：有趣且安全，一个具体信息 + 一个轻问题，不查户口；
  2. 熟一点：自曝换自曝，先给自己的具体小事，再轻轻问她同类的一件；
  3. 有点暧昧：造只有两人懂的默契（小称呼、拎回旧梗、故意留一句"回头说"）；
  4. 想见：给画面感的具体邀约（时间+地点+感觉），允许她说不，不追问理由。
- **【怎么像人】**：一条只做一件事；具体胜过抽象（"你周末是出门那种，还是窝着点外卖那种"而不是"你平时喜欢做什么"）；幽默三招（夸张/错位/自嘲）；推拉要轻且给糖；留白、不用"哈哈"填缝、不连发两条；她敷衍只加温一步，连冷两次收线。
- **【绝对不做】**：不索要微信/QQ/电话/住址，不谈钱，不性暗示，不评价身材，不 PUA 不装可怜，不查户口，不重复上条，不提"脚本/AI/托管"。
- **【反例 + 判断标准】**：明确列出"你平时喜欢做什么 / 那你呢 / 今天天气不错 / 哈哈真有意思 / 你也喜欢旅游吗 / 突然想起这事儿"，并要求"这句话至少有一个具体东西（一件事、地点、时间、物件），否则重写"。

### 2.2 阶段机 `stageOf`

按对话条数 + 末句关键词判定，不依赖模型自评：

```js
if (/见面|出来|约|有空|在哪|一起|见你/.test(最后一句)) return '想见';
if (总条数 <= 4) return '陌生';
if (总条数 <= 12) return '熟一点';
return '有点暧昧';
```
（星缘阈值 4/12，缘起与 nvda 为 3/9，因为后者节奏更快。）

### 2.3 固定回复的残留：只剩三条安全兜底

`ruleReply()` 只处理两种"必须硬回"的场景，其余全交模型：
- 她说"不想聊/别联系/别烦我/滚" → "行，那不打扰了。"
- 她说"我男的" → "行，那就不打扰了。"

这是刻意的：早期用固定套话回复，用户直接否掉（"不要固定回复"）。

### 2.4 输出过滤 + 防重复

- `clean()`：去引号、去换行、去"承接/调侃/轻推/回复："这类前缀、截断 45~48 字、命中禁词（微信/QQ/支付宝/转账/红包/手机号/加我/抖音）直接判空。
- `replyFor()` 二次校验：命中 `/你呢|你平时喜欢|今天天气|想起这事/` 就**重生成一次**，再中就不发（宁可不发，也不发套话）。
- 本地记忆 `memAppend`：每个对象存最近 5~8 条"我说过的话"，拼进 prompt，防复读。
- 生成参数：`temperature 0.85`、`max_tokens 150`、模型 `glm-4-plus`（智谱）。

### 2.5 面板规范（三站统一审美，用户逐条提过）

- 主面板只放开关；间隔/模型/Key 收进「设置」折叠区。
- 状态三行（在线状态 / 今日统计 / 下次执行）**进来就有**，直接由内存变量渲染，绝不写"检测中…"占位。
- 星缘额外做了面板自愈：`#xy-panel` 带 `dataset.owner`，每秒校验，发现旧实例残留就整块重建（历史上"面板假死"的根因就是 HTML 里写死了"状态：检测中…" + 残留旧面板被 `getElementById` 取到）。
- 站点 CSS 会覆盖按钮样式时，用 `#xx-panel .xx-setrow button` + `!important` 顶回去。
- 模型只在启动测一次 + 手动按钮，**不自动复测**。

### 2.6 时间真实性

`nowLine()` 生成"凌晨/早上/上午/中午/下午/晚上/深夜 + HH:MM"塞进 system，并要求"提到时段必须与实际一致，拿不准就不提"。用户明确讨厌模型在半夜说"早上好"。

## 3. 星缘（starfate.vip）· v1.9

### 3.1 核心结论：设置接口被拒 → 改客户端筛女生

- 站点真实匹配字段是**驼峰** `{gender, position, minAge, maxAge}`，早期脚本发的是 snake_case，故 400。
- 更关键：`POST /api/match/settings` 这个接口本身被拒（400）。用户拍板"设置接口被拒就别做了，改客户端筛女生"。
- **现行实现**：彻底删掉 `/api/match/settings` 调用；只 `POST /api/match/start`，拿 `/api/match/status` 的 `status.user.gender`（`'female'`）在客户端筛；男号**直接换人**（v1.9 起不再记黑名单）。

### 3.1b v1.9 变更：去掉男号黑名单（2026-11-23）

**为什么去**：用户原话"本来男生就跳过，干嘛还要男生拉黑"。黑名单在这里是纯负担：

- 男生本来就是"看到即离开→重新匹配"，不会再被匹配一次，名单没有实际过滤收益；
- `xy_us_black` 只增不减，跑一晚上能上千条，每轮 `JSON.parse` + `includes()` 线性扫描，是隐性卡顿源之一；
- 名单会和站点实际的"谁在线"脱节，反而可能误伤改了资料/换了性别的人。

**改了什么**：

- 删 `LS.black = 'xy_us_black'` 键；删 `BLACK()` / `addBlack()` 定义；
- 删 `autoReplyOnce()` 里 `if (black.includes(c.peerNickname)) continue;`；
- 删 `pickOnce()` / `matchOnce()` 里配到男号时的 `addBlack(u.nickname)`；
- 文件头部一次性 `localStorage.removeItem('xy_us_black')` 清历史数据；
- 日志保留"男号跳过（不拉黑）"，面板文案改为"男号见面即换人，不再拉黑记名单"。

**顺带**：面板渲染从每秒 `renderAll()` 改为 2 秒一次（见 §13 卡顿分析）。

### 3.2 接口清单（实测）

| 用途 | 方法/路径 | 说明 |
|---|---|---|
| 会话列表 | `GET /api/chat/conversations` | `data[]` 含 `id, peerNickname, unread, isDeleted, peerIsBanned` |
| 消息 | `GET /api/chat/conversations/{cid}/messages?pageSize=10` | `data[]` 含 `isSelf, text, createdAt` |
| 建会话 | `POST /api/chat/conversations` body `{targetUserId}` | 返回 `data.id` |
| 发消息 | `POST /hubs/chat/negotiate?negotiateVersion=1` 拿 connectionToken → `wss://… /hubs/chat?id=…&access_token=…` | SignalR JSON over WS |
| 捞在线 | `POST /api/match/pick-online` | `data.user{id,nickname,gender,age}`、`data.remainingPicks` |
| 随机匹配 | `POST /api/match/start` | 空 body 即可 |
| 匹配状态 | `GET /api/match/status` | `status==='matched'` 且 `data.user` |

### 3.3 SignalR 发送帧（这是最容易被写错的地方）

```
握手: ws.send(JSON.stringify({protocol:'json',version:1}) + '\u001e')
发送: ws.send(JSON.stringify({
        type:1, invocationId:'1', target:'SendMessage',
        arguments:[{conversationId:cid, text, msgType:'text', burnAfterRead:false, replyToId:null}]
      }) + '\u001e')
完成: 收到 type:3 且 invocationId==='1' → error 为空即成功
```
注意每条帧都带 **`\u001e`（RS 分隔符）**，漏了就永远没有回执。

### 3.4 发送队列

所有发送走 `enqueueSend()` 串行，最小间隔 900ms——早期并发发消息会互相堵死。

### 3.5 三条运行路径

- **自动回复** `autoReplyOnce()`：只处理 `unread>0` 的会话（省请求），跳过已删/对方被封/黑名单；末条是我就跳过；`sent` 表按 `会话|时间|文本` 去重；一轮最多 3 条，每条间隔 1.2s。
- **自动捞在线** `pickOnce()`：每轮最多 20 次，`remainingPicks<=0` 立即停；女号才建会话打招呼，男号进黑名单。
- **自动随机匹配** `matchOnce()`：连续循环——发起 → 每秒轮询 status 最多 `matchPoll` 秒 → 男号冷却换人 / 女号建会话打招呼 → 继续下一轮；整轮无人则 30 秒后重试。

### 3.6 已知问题（见 §9.1，未修）

- `testModel()` 里 `log(MODEL.ok ? …)` 用的是 `MODEL.ok`，实际字段是 `MODEL.state` → 日志恒打"模型测试失败"（功能本身没坏）。
- "回复 0 条"统计不准：`pushStat()` 只写 `recent` 列表，没累加 `st.replied`；`autoReplyOnce()` 成功后也没累加。这是用户截图里"捞取 124 次 · 回复 0 条"的直接原因。
- token 长期为空（`localStorage.token` 不存在）→ 所有 REST 401，脚本只能待命；需用户手动在站内登录。

## 4. 缘起（nmliao.cc）· v1.9

### 4.1 协议要点（踩了很久才通）

- 复用**页面自己的** socket.io 连接，不自建第二条（第二条会被服务端当成另一个会话）。
- 帧格式：`42[event, payload]`，**没有 ack id**；`payload` 若是数组要展开成多个元素（`42["start_match", uid, setting]`），否则服务端当非法参数丢掉。
- 必须回 ping：收到 `'2'` 立刻回 `'3'`。
- 推送是 `42` 里带 `{func:'…', data:{…}}` 的对象，可能是字符串，要再 `JSON.parse` 一次。
- **只认页面 socket 且要求 `__recv>=2`**（页面自己已经收到过帧）才发，否则帧被吞。

### 4.1b v1.9 变更：去掉男号黑名单（2026-11-23）

与星缘同一决定、同一改法：删 `LS.black='nm_us_black'`、删 `addBlack()` 与 `black.includes(c.title)` 过滤、删 `onMatched` / `pickOnce` 里的写入、头部 `removeItem('nm_us_black')` 清历史。面板渲染 `setInterval(render,1000)` → `2000`。

### 4.2 事件表

| 方向 | 事件 | 载荷 |
|---|---|---|
| 发 | `start_match` | `[uid, {gender:'female'|'any', position:'any', min_age:18, max_age:70}]` |
| 发 | `quit_match` | `uid` |
| 发 | `send_msg` | `{message_id, uid, to_uid, chatid, msg:{msg_type:'text', msg_content, msg_meta:{}}, is_group_chat:false, force_green:false}` |
| 收 | `match_result` | `data{nickname, gender:'female'|'male', id, match_id, age}` |
| 收 | `recv_msg` | `data{uid, msg_content…}` |
| 收 | `update_msgs_status` | `data.status`（`isSend` 忽略） |

### 4.3 REST

| 用途 | 路径 | 备注 |
|---|---|---|
| 我的信息 | `POST /api/v1/user/get_info` | 返回 `id/token/gender/nickname` |
| 会话列表 | `POST /api/v1/anonchat/load_more_chats` `{from_id:null, limit:40}` | 每项含 `chatid, title, to_uid, unread_msg_count, is_block, other_leave` |
| 消息 | `POST /api/v1/anonchat/load_more_messages` `{chatid, from_id:null, limit:20, is_group_chat:false}` | |
| 建会话 | `POST /api/v1/anonchat/start_chat` `{from:'match', token:<match_id>}` | **`token` 字段名骗人，实际要传 match_id**；返回 `{chatid, to_uid, uid}` |

### 4.4 弹窗/遮罩处理（血的教训）

- 站点会在 `match_result` 后弹"重新匹配/开始聊天"卡片，还带 `.adm-mask.adm-center-popup-mask` 遮罩 + `body.adm-overflow-hidden` 滚动锁。
- **禁止用 `remove()`**：React 复用节点，删了会 `insertBefore` 报错。
- **禁止 MutationObserver + 每 2 秒全量 `innerText` 扫描**：直接把浏览器拖到卡死（用户原话"宁可自己弄也不接受卡顿"）。
- 现行做法：`match_result` 到达后 1.5 秒收一次（`textContent`），匹配卡片 `display:none + pointer-events:none` 并打 `dataset.nmSkip`；无可见弹层时，把残留遮罩一起 `display:none` 并 `body.classList.remove('adm-overflow-hidden')`。

### 4.5 匹配循环

`quit_match` → 停 1.2s → `start_match` → 等 `matchWait`（默认 20s）→ 没结果就重发。配到男号：记黑名单、冷却 `matchGap`（默认 10s）再配；配到女号：`start_chat` 建会话 → `send_msg` 发「哈喽」。

### 4.6 已知问题

- `pickOnce()` 靠 DOM 点「捞个在线」+ 读弹窗文本判性别，站点改版就失效（当前默认关闭，每天只有 5 次）。
- `setting` 里用 `min_age/max_age`（snake_case）能配上，但与星缘驼峰命名不一致，属未验证项，改版时优先怀疑这里。

## 5. nvda.chat · v1.2

### 5.1 站点结构

- Vue3 SPA，主包 `https://nvda.chat/assets/index-DGSXETHT.js`（约 894KB，可 grep 协议细节），CSS `/assets/index-BhVPetDM.css`，REST 前缀 `https://nvda.chat/nd`。
- 首页 socket 是**懒连接**：不点「开始匹配」就不 connect。脚本的 `bootstrapOnce()` 只点一次把连接拉起来，之后全走帧。
- 匿名可用：连上先发 `verifyAuth{components:<fingerprint>}`，服务端回 `42["authSuccess",{data:{userToken}}]`，脚本接住写进 `ST.token`。

### 5.2 连接参数

```js
io("https://nvda.chat", {
  query: { tabId, userData: JSON.stringify({accessToken, userToken, version:"10000", platform:"H5", channel, fingerprint, deviceInfo}) },
  transports: ["websocket","polling"]
});
```

### 5.3 帧格式（socket.io v4）

- 客户端 emit 带 ack id：`42<id>["event", payload]`，实测 `421["match",…]`、`429["sendMessage",…]`
- 服务端推送不带 id：`42["matchSuccess",{…}]`
- ack 回包：`43<id>[{code,msg,data}]`

### 5.4 事件表

| 方向 | 事件 | 载荷 |
|---|---|---|
| 发 | `match` | `{nicknameId:"<localStorage nicknameId>", age:20, gender:"0", agentMatch:false}` |
| 发 | `cancelMatch` | — |
| 发 | `leaveMatch` | `{matchId}` |
| 发 | `sendMessage` | `{matchId, content, messageType:"text", quotation:null, quotationContent:null, mediaId:null, extraInfo:null}` |
| 收 | `matchSuccess` | `{code:0, data:{matchId, nickname, age, gender, lastCity}}` |
| 收 | `matchFailed` | — |
| 收 | `receiveMessage` | `{data:{messageId, matchId, content, messageType, createDate, safety}}` |
| 收 | `closeChat` | `data` = matchId |
| 收 | `messageRevoke` / `error` | `error 1109`=同账号他处登录，`1100`=reload |

### 5.5 三个必须记住的语义

1. **`gender` 是"我自己的性别"**（站点 UI radio 0=男/1=女），不是筛选条件。写 `"1"` 会招来一堆男号性挑逗机器人，写 `"0"` 一样男多女少。**v1.2 固定 `myGender:'0'`**，不再读 localStorage（v1.0 曾读，可能残留用户手点的"女"）。
2. **异性匹配是会员功能**（`POST /account/preferredGender/{bool}`，非会员点了只弹"开通会员可启用异性匹配"）→ 筛女生只能客户端做。
3. **`instruction 9110` = 站点静默拦截**。翻主包源码：`if (De.code != 9110) {…}` 才弹提示，也就是 9110 被吞得无声无息（消息既不进对话也不报错）。实测连"哈喽"都会被吞。

### 5.6 REST（可独立调用，注意带 token）

| 用途 | 路径 |
|---|---|
| 单个会话详情 | `GET /nd/match/{matchId}?token=<userToken>` → `matchId/nickname/age/gender/city/close/messages[]/agent/dangerousUser/tags/testGame` |
| 会话列表 | `GET /nd/match/list?token=` → 含 `unreadCount、messageId、close` |
| 工具类 | `/nd/tools/nickname`、`/nd/tools/memeList`、`/nd/tools/replySuggest` |
| 其他 | `/nd/match/collect/{id}`、`/nd/match/black/{id}`、`/nd/system/message/page`、`/nd/auth/needMobile` |

### 5.7 并行会话（这是本站最大特点）

- 聊天中直接再发 `match` 帧会生成**新 matchId**，旧会话 `close:false` 仍在、仍能 `sendMessage`（ack code 0）。→ "边聊边配"成立。
- **但**实测连建 3 个会话后，30 秒内只有**最新会话**收到 `receiveMessage` 推送。所以 v1.1 起加了 REST 兜底：每 20s 拉 `/nd/match/list`，对 `unreadCount>0` 或 `messageId` 变了的会话 `GET /nd/match/{id}` 重同步历史再决定回复。
- 结构从"单会话 `ST.cur`"改为 `CHATS` map（`matchId → {nickname,age,gender,hist,lastRepliedId,nextAt,lastSeen}`），消息按 `matchId` 分流。
- `keepMatching` + `maxChats`（默认 3）控制并行；跳过时不动任何对话框，纯帧 `leaveMatch` 后 2 秒换人。

### 5.8 v1.2 新增（用户点名要的三件）

1. **侧栏男女标注**：每 12s 拉 `/nd/match/list`，往 `.match-item-name .partner-name-row > span` 里插 `nvda-icon-girl/boy + chat-partner-info-icon`，颜色 `#ff4d6d`/`#1677ff`（沿用用户 v10.5 的类名与配色，站点刷新样式也不会盖掉）。新配到的人先塞本地缓存，侧栏立刻可见。
2. **打招呼自定义 + 可两句**：设置里 `打招呼（最多两句，用 | 隔开）`，默认 `哈喽`；`哈喽|刚下班，瘫一会儿` 分两条发，中间隔 `greetGap`（默认 3s）；她若先开口就不再补第二句。静态文本不走模型、不吃 token。
3. **悬浮狗头改 SVG**：原 emoji `🐶` 受字体与 line-height 影响在圆里偏下偏左；改为手绘 SVG + flex 居中，实测 26px 图标在 46px 圆内偏移 (10,10)。

### 5.9 发送失败重试

非 0 ack → 把这条从 `hist` 撤掉 → 9~16 秒随机延迟重发一次 → 仍失败记日志放弃。9110 单独映射文案"被站点拦截（疑似太频繁或触了敏感）"。

### 5.10 关于"页面还是会进会话页"

站点自己的 Vue 收到 `matchSuccess` 就会切会话、开聊天层，拦不住也不该拦（改 store / pushState 正是之前弹窗卡死的源头）。不影响后台：在会话页里继续发 `match` 照样能配、旧会话不关。

## 6. 机器人与男号识别规则（跨站可复用）

**男号**：`gender !== 1`（nvda）/ `!=='female'`（星缘、缘起）→ 直接跳过，不碰对话框。

**机器人/假号特征**（按命中率排序）：

| # | 特征 | 处理 |
|---|---|---|
| 1 | 开场即性挑逗，且 3~10 秒内到达（奶子多大/看看/可以调教我吗主人/叫爸爸/你还是处女吗？/水多吗/第一次多大/可以玩我吗/不正经的聊不） | 正则命中即刻 `leaveMatch`，标签"机器人/擦边" |
| 2 | 广告引流（加微信/扣扣/telegram/日赚/刷单/博彩/色播/视频一对一） | 同上 |
| 3 | `age === 0` 或明显假年龄 | 记黑名单、跳过 |
| 4 | **人设复用**：同"昵称|年龄"出现 >2 次（实测"你带的/21"两次、宇宙幽灵魔 matchId 被复用） | 跳过 |
| 5 | `agent === true`（勾了"探索智能体"进来的） | 跳过 |
| 6 | `dangerousUser === true` | 跳过 |
| 7 | 城市大量"保密"、回复间隔几乎恒定 | 综合判据，可加权 |
| 8 | 自述未成年/学生（未成年/17岁/初中/高一/还没成年） | 被动收线，不推进（不主动查年龄，`minAge` 默认 0） |

采样背景（nvda.chat 约 30 个匹配、00:45–02:10 时段）：绝大多数是男号；标"女"的极少且多为假（钢刃雷耀王女/0岁、神秘法师兔女/26 沉默、梅影挽明寒女/17）；**所有主动开口的 100% 是性挑逗开场**。

## 9. 已知问题与待办

### 9.1 待修（按优先级）

1. **星缘统计"回复 0 条"**：`pushStat()` 与 `autoReplyOnce()` 都没累加 `st.replied` → 在发送成功后 `st.replied = (st.replied||0)+1`；打招呼是否单独计数待用户拍板（历史问过两次未答）。
2. **星缘 `testModel()` 里 `MODEL.ok`** → 应为 `MODEL.state === 'ok'`。
3. **星缘 token 为空**：需用户在站内手动登录一次；脚本已能待命并在登录后接管，但云主机曾长期 401。
4. 三站都**只处理文本消息**，对方发图片/语音/表情时会当成空文本跳过（可能表现为"已读不回"）。
5. nvda 非当前会话依赖 20s 轮询兜底 → 最坏延迟 20 秒才回；是否缩短间隔或强制 `maxChats=1` 未定。
6. 缘起 `setting` 的 `min_age/max_age` 命名未与站点源码核对。
7. 星缘 `matchOnce()` 与 `pickOnce()` 的打招呼都没进 `st.chats` 统计，面板"开聊"数永远偏低。

### 9.2 未决

- 星缘"今日捞取 124 次 / 回复 0 条"是否拆成"打招呼 / 回复"两栏。
- 星缘定时任务（doubao-cron-scheduler）连续多轮因登录态失效空转，是否关闭待定。

  // 智谱走 GM_xmlhttpRequest，绕过跨域限制（浏览器直连 open.bigmodel.cn 会被 CORS 拦）
  function llmPost(body) {
    return new Promise((resolve, reject) => {
      const payload = JSON.stringify(body);
      const headers = { 'Authorization': 'Bearer ' + KEY(), 'Content-Type': 'application/json' };
      if (typeof GM_xmlhttpRequest === 'function') {
        GM_xmlhttpRequest({
          method: 'POST', url: LLM_URL, headers, data: payload, timeout: 30000,
          onload: r => resolve({ ok: r.status >= 200 && r.status < 300, text: r.responseText }),
          onerror: () => reject(new Error('network')),
          ontimeout: () => reject(new Error('timeout')),
        });
      } else {
        fetch(LLM_URL, { method: 'POST', headers, body: payload })
          .then(r => r.text().then(t => resolve({ ok: r.ok, text: t })))
          .catch(reject);
      }
    });
  }

  async function gen(prompt, maxTokens = 90) {
    for (let i = 0; i < 3; i++) {
      try {
        const r = await llmPost({
          model: LLM_MODEL,
          messages: [{ role: 'system', content: SYS }, { role: 'user', content: prompt }],
          temperature: 0.85, max_tokens: maxTokens
        });
        if (!r.ok) { await sleep(1500); continue; }
        const j = JSON.parse(r.text);
        const t = ((j.choices && j.choices[0] && j.choices[0].message.content) || '').trim();
        if (t) return clean(t);
      } catch (e) { await sleep(1500); }
    }
    return '';
  }

  const BAN = ['微信', 'QQ', 'qq', 'vx', '支付宝', '转账', '红包', '手机号', '加我', '抖音'];
  function clean(t) {
    t = t.replace(/^["“'「]|["”'」]$/g, '').replace(/\n+/g, ' ').trim();
    t = t.replace(/^(承接|降压|调侃|轻推|约见|澄清|收线|回复)[：:]\s*/, '').trim();
    if (t.length > 45) t = t.slice(0, 45);
    if (BAN.some(w => t.includes(w))) return '';
    return t;
  }

  function stageOf(norm) {
    const total = norm.length;
    const last = (norm[norm.length - 1] || {}).t || '';
    if (/见面|出来|约|有空|在哪|一起|见你/.test(last)) return '想见';
    if (total <= 4) return '陌生';
    if (total <= 12) return '熟一点';
    return '有点暧昧';
  }

  // 只保留安全兜底；其余全部交给模型（避免固定套话）
  function ruleReply(msgs) {
    const L = ((msgs[msgs.length - 1] || {}).t || '').trim();
    if (/不想聊|别联系|不要联系|不欢迎|别烦我|滚/.test(L)) return '行，那不打扰了。';
    if (/我男的|我是男的|性别男/.test(L)) return '行，那就不打扰了。';
    return '';
  }


  async function replyFor(name, msgs) {
    const norm = msgs.map(m => ({ s: m.isSelf ? 1 : 0, t: m.text || '', time: (m.createdAt || '').slice(11, 16) }));
    const r = ruleReply(norm);
    if (r) return r;
    const stage = stageOf(norm);
    const said = ((memAll()[name] || {}).said || []).slice(-5);
    const lines = norm.slice(-8).map(m => (m.s ? '我：' : name + '：') + m.t).join('\n');
    const last = norm[norm.length - 1].t;
    const hints = [];
    if (/\?|？|吗/.test(last)) hints.push('她在问我：先把她问的答完，最多再轻轻带一句。');
    const prevSelf = [...norm].reverse().find(m => m.s);
    if (prevSelf && /[？?]$/.test(prevSelf.t)) hints.push('上一条我已经问过问题了，这次不要再用问句。');
    const out = await gen(`对象：${name}\n当前阶段：${stage}\n我之前对她说过：${said.length ? said.join('；') : '（还没有）'}\n最近聊天：\n${lines}\n${hints.join('\n')}\n写出我下一条，不要重复我说过的话。`, 150);
    const bad = /你呢|你平时喜欢|今天天气|想起这事/;
    if (!out) return '';
    if (bad.test(out)) {
      const again = await gen(`对象：${name}\n当前阶段：${stage}\n最近聊天：\n${lines}\n换一句：不许出现"你呢/你平时喜欢/今天天气"，必须带一个具体细节（地点、时间、动作或物件）。`, 120);
      if (again && !bad.test(again)) return again;
      return '';
    }
    return out;
  }


  // ---------- 自动回复 ----------
  async function autoReplyOnce() {
    const convs = await getConvs();
    const black = BLACK();
    const sent = loadLS(LS.sent, {});
    let done = 0;
    for (const c of convs) {
      if (done >= S.maxReplyPerRound) break;
      if (c.isDeleted || c.peerIsBanned) continue;
      if (c.unread === 0) continue;   // 只处理有未读的，省请求
      if (black.includes(c.peerNickname)) continue;
      const msgs = await getMsgs(c.id, 10);
      if (!msgs.length) continue;
      const last = msgs[msgs.length - 1];
      if (last.isSelf) continue;                     // 我方已最后发言，不追加
      const key = c.id + '|' + (last.createdAt || '') + '|' + (last.text || '');
      if (sent[key]) continue;                        // 同一条已处理过
      const reply = await replyFor(c.peerNickname, msgs);
      if (!reply) { log('跳过 ' + c.peerNickname + '（模型空或触发禁词）'); sent[key] = 1; saveLS(LS.sent, sent); continue; }
      const prevSelf = [...msgs].reverse().find(m => m.isSelf);
      if (prevSelf && prevSelf.text === reply) { log('跳过 ' + c.peerNickname + '（与上条重复）'); sent[key] = 1; saveLS(LS.sent, sent); continue; }
      try {
        await enqueueSend(() => hubSend(c.id, reply));
        sent[key] = 1; saveLS(LS.sent, sent);
        done++;
        log('回复 ' + c.peerNickname + '：' + reply);
        pushStat(c.peerNickname, reply);
        memAppend(c.peerNickname, reply);
        await sleep(1200);
      } catch (e) { log('发送失败 ' + c.peerNickname + '：' + e.message); }
    }
  }

  async function matchOnce() {
    // 连续匹配：男的换下一个，女的打招呼后继续，直到关开关或连续超时
    for (let round = 0; round < 99999 && S.autoMatch; round++) {
      let ok = false;
      try {
        await api('/api/match/start', { method: 'POST', body: '{}' });
      } catch (e) { log('发起匹配失败：' + e.message); await sleep(3000); continue; }
      log('发起随机匹配（客户端只接女生）');

      const poll = Math.max(5, S.matchPoll || 30);
      for (let i = 0; i < poll && S.autoMatch; i++) {
        await sleep(1000);
        let st;
        try { st = (await api('/api/match/status')).data; } catch { continue; }
        if (!st) continue;
        const u = st.user;
        if (st.status !== 'matched' || !u) continue;
        ok = true;
        if (S.femaleOnly && u.gender !== 'female') {
          addBlack(u.nickname);
          log('配到男号 ' + u.nickname + '，换下一个（冷却 ' + (S.matchGap || 8) + ' 秒）');
          await sleep(Math.max(2, S.matchGap || 8) * 1000);
          break;
        }
        const cid = await createConv(u.id);
        if (cid) {
          const msg = await greeting(u);
          try {
            await enqueueSend(() => hubSend(cid, msg));
            log('配到 ' + u.nickname + '(' + u.gender + '/' + u.age + ')：' + msg);
            pushStat(u.nickname, msg);
          } catch (e) { log('打招呼失败：' + e.message); }
        }
        await sleep(Math.max(2, S.matchGap || 8) * 1000);
        break;    // 女生处理完，继续下一轮
      }
      if (!ok) { log('这一轮没配到人（队列超时），30 秒后重试'); await sleep(30000); }
    }
  }

    return new Promise((resolve, reject) => {
      const payload = JSON.stringify(body);
      const headers = { 'Authorization': 'Bearer ' + KEY(), 'Content-Type': 'application/json' };
      if (typeof GM_xmlhttpRequest === 'function') {
        GM_xmlhttpRequest({
          method: 'POST', url: LLM_URL, headers, data: payload, timeout: 30000,
          onload: r => resolve({ ok: r.status >= 200 && r.status < 300, text: r.responseText }),
          onerror: () => reject(new Error('network')),
          ontimeout: () => reject(new Error('timeout')),
        });
      } else {
        fetch(LLM_URL, { method: 'POST', headers, body: payload })
          .then(r => r.text().then(t => resolve({ ok: r.ok, text: t })))
          .catch(reject);
      }
    });
  }

  async function gen(prompt, maxTokens = 90) {
    for (let i = 0; i < 3; i++) {
      try {
        const r = await llmPost({ model: LLM_MODEL, messages: [{ role: 'system', content: SYS }, { role: 'user', content: prompt }], temperature: 0.85, max_tokens: maxTokens });
        if (!r.ok) { await sleep(1500); continue; }
        const j = JSON.parse(r.text);
        const t = ((j.choices && j.choices[0] && j.choices[0].message.content) || '').trim();
        if (t) return clean(t);
      } catch (e) { await sleep(1500); }
    }
    return '';
  }

  const BAN = ['微信', 'QQ', 'qq', 'vx', '支付宝', '转账', '红包', '手机号', '加我', '抖音'];
  function clean(t) {
    t = t.replace(/^["“'「]|["”'」]$/g, '').replace(/\n+/g, ' ').trim();
    t = t.replace(/^(承接|降压|调侃|轻推|约见|澄清|收线|回复)[：:]\s*/, '').trim();
    if (t.length > 45) t = t.slice(0, 45);
    if (BAN.some(w => t.includes(w))) return '';
    return t;
  }

  function stageOf(norm) {
    const total = norm.length;
    const last = (norm[norm.length - 1] || {}).t || '';
    if (/见面|出来|约|有空|在哪|一起|见你/.test(last)) return '想见';
    if (total <= 4) return '陌生';

  // 只保留安全兜底；其余全部交给模型（避免固定套话）
  function ruleReply(msgs) {
    const L = ((msgs[msgs.length - 1] || {}).t || '').trim();
    if (/不想聊|别联系|不要联系|不欢迎|别烦我|滚/.test(L)) return '行，那不打扰了。';
    if (/我男的|我是男的|性别男/.test(L)) return '行，那就不打扰了。';
    return '';
  }


  const normOf = list => list.map(m => ({ s: (m.uid === ME.id) ? 1 : 0, t: m.msg_content || m.content || '' })).filter(m => m.t);

  async function replyFor(name, list) {
    const norm = normOf(list);
    if (!norm.length) return '';
    const r = ruleReply(norm);
    if (r) return r;
    const stage = stageOf(norm);
    const said = ((memAll()[name] || {}).said || []).slice(-5);
    const lines = norm.slice(-8).map(m => (m.s ? '我：' : name + '：') + m.t).join('\n');
    const last = norm[norm.length - 1].t;
    const hints = [];
    if (/\?|？|吗/.test(last)) hints.push('她在问我：先把她问的答完，最多再轻轻带一句。');
    const prevSelf = [...norm].reverse().find(m => m.s);
    if (prevSelf && /[？?]$/.test(prevSelf.t)) hints.push('上一条我已经问过问题了，这次不要再用问句。');
    const out = await gen(`对象：${name}\n当前阶段：${stage}\n我之前对她说过：${said.length ? said.join('；') : '（还没有）'}\n最近聊天：\n${lines}\n${hints.join('\n')}\n写出我下一条，不要重复我说过的话。`, 150);
    const bad = /你呢|你平时喜欢|今天天气|想起这事/;
    if (!out) return '';
    if (bad.test(out)) {
      const again = await gen(`对象：${name}\n当前阶段：${stage}\n最近聊天：\n${lines}\n换一句：不许出现"你呢/你平时喜欢/今天天气"，必须带一个具体细节（地点、时间、动作或物件）。`, 120);
      if (again && !bad.test(again)) return again;
      return '';
    }
    return out;
  }

    if (!readySock()) { log('socket 未就绪，5 秒后重试'); M.until = now + 5000; nextRun.match = M.until; return; }
    const setting = { gender: S.femaleOnly ? 'female' : 'any', position: 'any', min_age: 18, max_age: 70 };

    M.phase = 'waiting'; M.until = now + wait * 1000; nextRun.match = M.until;
    sendOnSock('quit_match', ME.id);
    await sleep(1200);

    if (ok) log('socket 发起匹配（' + (S.femaleOnly ? '只女生' : '不限性别') + '），等 ' + wait + ' 秒');

  }

      const tries = opt.retry || 0;
      if (!opt.noRetry && tries < 1) {
        const wait = 9000 + Math.random() * 7000;
        log('9~16 秒后重发一次：' + text.slice(0, 12));
        setTimeout(() => {
          if (!CHATS[matchId]) return;
          sendMsg(matchId, text, { retry: tries + 1 });
        }, wait);
      } else if (tries >= 1) {
        log('重发仍被拒，这条放弃：' + text.slice(0, 12));
      }
    };
    return true;
  }

  // 打招呼：静态文本，不走模型；支持两个句子，用 | 或 ｜ 隔开
function greetParts() {
  const raw = String(S.greet == null ? '哈喽' : S.greet);
  const ps = raw.split(/\s*[|｜]\s*|\r?\n+/).map(x => x.trim()).filter(Boolean).slice(0, 2);
  return ps.length ? ps : ['哈喽'];
}
function greet(c) {
  const parts = greetParts();
  c.greeted = true;
  if (!sendMsg(c.matchId, parts[0])) { log('打招呼发送失败 ' + c.nickname); return; }
  log('打招呼 ' + c.nickname + '：' + parts[0] + '（共 ' + chatList().length + ' 个会话）');
  if (parts.length < 2) return;
  const gap = Math.max(1, Number(S.greetGap) || 2) * 1000 + Math.random() * 800;
  setTimeout(() => {
    const live = CHATS[c.matchId];
    if (!live) return;
    const last = live.hist[live.hist.length - 1];
    if (!last || last.s !== 1) return;       // 她先说话了就不再补第二句，免得抢话
    if (sendMsg(c.matchId, parts[1])) log('补第二句 ' + live.nickname + '：' + parts[1]);
    else log('第二句没发出去 ' + live.nickname);
  }, gap);
}

async function onMatched(d) {
    if (!d || !d.matchId) return;
    if (CHATS[d.matchId]) return;
    bump('matched');
    try { SIDE.list.unshift({ matchId: d.matchId, nickname: d.nickname, age: d.age, gender: d.gender }); } catch (_) {}
    const peer = {
      matchId: d.matchId, nickname: d.nickname || '对方', age: Number(d.age || 0),
      gender: Number(d.gender), city: d.lastCity || '', at: Date.now(),
      greeted: false, hist: [], lastRepliedId: '', nextAt: 0, lastSeen: '',
    };
    log('配到 ' + peer.nickname + '（' + (peer.gender === 1 ? '女' : '男') + '/' + (peer.age || '?') + '）');

    const skip = (reason, stat) => {
      bump(stat || 'skipBot');
      log('跳过 ' + peer.nickname + '（' + reason + '）→ 立刻换人');
      sendRaw('leaveMatch', { matchId: peer.matchId }, 8200 + Math.floor(Math.random() * 900));
      nextRun.match = Date.now() + Math.max(1, S.matchGap) * 1000;
      render();
    };

    if (S.femaleOnly && peer.gender !== 1) return skip('男号', 'skipMale');
    if (S.minAge && peer.age && peer.age < S.minAge) return skip('年龄 ' + peer.age);

    const det = await detail(peer.matchId);
    if (S.botFilter && det && det.agent === true) return skip('官方智能体');
    if (S.botFilter && det && det.dangerousUser === true) return skip('风险账号');
    if (S.botFilter && S.skipRepeat) {
      const c = peerMark(peer.nickname + '|' + peer.age);
      if (c > 2) return skip('同人设第 ' + c + ' 次出现');
    }

    CHATS[peer.matchId] = peer;
    bump('chats');
    greet(peer);
    if (S.keepMatching && chatList().length < Math.max(1, S.maxChats)) {
      nextRun.match = Date.now() + Math.max(1, S.matchGap) * 1000;
    }
    render();
  }

  function onRecv(d) {
    if (!d || !d.matchId) return;
    const text = String(d.content || '');
    if (!text) return;
    const c = CHATS[d.matchId];
    if (!c) { sendRaw('leaveMatch', { matchId: d.matchId }, 8400 + Math.floor(Math.random() * 90)); return; }
    const last = c.hist[c.hist.length - 1];
    if (last && last.s === 0 && last.t === text) return;
    c.hist.push({ s: 0, t: text, id: d.messageId });
    if (d.messageId) c.lastSeen = d.messageId;
    log('收 ' + c.nickname + '：' + (text.length > 14 ? text.slice(0, 14) + '…' : text));

    if (S.botFilter && (SEX.test(text) || AD.test(text))) {
      bump('skipBot');
      log(c.nickname + ' 发擦边/广告（' + text.slice(0, 12) + '）→ 直接走人');
      closeChat(d.matchId, '机器人/擦边');
      return;
    }
    if (MINOR.test(text)) {
      log(c.nickname + ' 提到未成年/学生 → 收线');
      closeChat(d.matchId, '未成年');
      return;
    }
    if (S.autoReply) {
      c.nextAt = Date.now() + Math.max(2, S.replyDelay + Math.random() * 3) * 1000;
      render();
    }
  }

  async function maybeReply(c) {
    if (!c || !S.autoReply) return;
    const h = c.hist;
    if (!h.length) return;
    const last = h[h.length - 1];
    if (last.s === 1) return;
    const key = last.id || ('t:' + last.t);
    if (c.lastRepliedId === key) return;
    c.lastRepliedId = key;
    const text = await replyFor(c.nickname, h);
    if (!text) { log('这次没生成出可发的话，先不发'); return; }
    if (!CHATS[c.matchId]) return;
    if (sendMsg(c.matchId, text)) {
      memAppend(c.nickname, text);
      bump('replies');
      log('回复 ' + c.nickname + '：' + text);
    }
    render();
  }

  // 兜底：从 REST 同步（推送只覆盖当前会话时靠这个不漏消息）
  async function syncChats() {
    if (!chatList().length) return;
    let list = [];
    try {
      const r = await fetch(`/nd/match/list?token=${encodeURIComponent(myId())}`, { credentials: 'include' });
      const j = await r.json();
      list = (j && j.data) || [];
    } catch (_) { return; }
    for (const c of chatList()) {
      const item = list.find(x => x.matchId === c.matchId);
      if (!item) { closeChat(c.matchId, '会话已不存在'); continue; }
      if (item.close === true) { closeChat(c.matchId, '会话已关闭'); continue; }
      if (item.unreadCount > 0 || (item.messageId && item.messageId !== c.lastSeen)) {
        const det = await detail(c.matchId);
        if (!det || !Array.isArray(det.messages)) continue;
        const mapped = det.messages.map(m => ({ s: m.self === 1 ? 1 : 0, t: String(m.content || ''), id: m.messageId }));
        c.hist = mapped;
        const nl = mapped[mapped.length - 1];
        if (item.messageId) c.lastSeen = item.messageId;
        if (nl && nl.s === 0 && S.autoReply) c.nextAt = Date.now() + Math.max(2, S.replyDelay) * 1000;
      }
    }
  }

    const s1 = document.getElementById('nv-stat');
    if (s1) s1.textContent = `今天：匹配 ${st.matched || 0} · 跳过男号 ${st.skipMale || 0} · 跳过机器人 ${st.skipBot || 0} · 开聊 ${st.chats || 0} · 回复 ${st.replies || 0}`;
    const n = document.getElementById('nv-next');
    if (n) {
      const now = Date.now();
      n.textContent = '下次：' + (S.autoMatch
        ? (chatList().length >= Math.max(1, S.maxChats) && !S.keepMatching
          ? '会话满了，暂停匹配'
          : '匹配 ' + Math.max(0, Math.round((nextRun.match - now) / 1000)) + ' 秒')
        : '匹配 关');
    }
  }

  function onPush(ev, data) {
    try {
      if (ev === 'authSuccess') {
        if (data && data.data && data.data.userToken) { ST.token = data.data.userToken; log('socket 认证通过'); render(); }
      }
      if (ev === 'matchSuccess') onMatched(data && data.data).catch(e => log('开聊异常：' + e.message));
      if (ev === 'matchFailed') { nextRun.match = Date.now() + 3 * 1000; log('匹配失败：' + ((data && data.msg) || '稍后重试')); }
      if (ev === 'receiveMessage') onRecv(data && data.data);
      if (ev === 'closeChat') {
        const id = data && data.data;
        if (CHATS[id]) { delete CHATS[id]; log('对方离开：' + String(id).slice(-6)); render(); }
      }
      if (ev === 'error' && data && data.code === 1109) log('同账号在别处登录，脚本暂停匹配');
    } catch (e) {}
  }

  function tick() {
    render();
    const now = Date.now();
    if (S.autoReply) {
      for (const c of chatList()) {
        if (c.nextAt && now >= c.nextAt) { c.nextAt = 0; maybeReply(c).catch(() => {}); }
      }
    }
    if (now >= nextRun.poll) { nextRun.poll = now + 20000; syncChats().catch(() => {}); }
    if (now >= nextRun.side) { nextRun.side = now + 12000; pullSideList().then(annotateSidebar).catch(() => {}); }
    if (now >= nextRun.sideA) { nextRun.sideA = now + 2500; annotateSidebar(); }
    if (S.autoMatch) matchLoop().catch(() => {});
    for (const c of chatList()) {
      if (c.greeted && c.hist.filter(m => m.s === 0).length === 0 && Date.now() - c.at > Math.max(30, S.giveUp) * 1000) {
        log(c.nickname + ' 一直没说话，走人');
        closeChat(c.matchId, '沉默');
      }
    }
  }

  function boot() {
    if (document.getElementById('nv-panel')) return;
    buildPanel();
    render();
    ST.token = localStorage.getItem('userToken') || '';
    const t0 = Date.now();
    nextRun.match = t0 + 2000;
    nextRun.poll = t0 + 5000;
    nextRun.side = t0 + 2000;
    log('助手已启动（' + (localStorage.getItem('nickname') || '匿名') + '）· 以男生身份匹配');
    setTimeout(() => testModel(true), 2000);
    setInterval(tick, 1000);
    setInterval(render, 2000);
  }

  if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', () => setTimeout(boot, 900));
  else setTimeout(boot, 900);
})();

## 11. 巧巧 / 迷迷（qiaoqiao.chat · mimiu.chat）· v1.0

> 编号接在 §10 之后追加，**没有重排既有章节**——因为正文里大量行内引用（§8 / §9.1 / §10）会因此错位。

### 11.1 一句话结论

这两站**没有自研 socket 协议**，聊天底座是页面内嵌的**网易云信 NIM v2**。硬啃 WebSocket 字节流是死路；正确姿势是**把页面里正在跑的那个 SDK 实例接管过来**，用它的 `V2NIMMessageService` 收发、用它的加解密模块解正文。两站共用同一份 bundle，靠域名切配置，所以**一份脚本两个 `@match` 就够**。

### 11.2 两站差异只有这几行

| 键 | 巧巧 `www.qiaoqiao.chat` | 迷迷 `www.mimiu.chat` |
|---|---|---|
| `mode` | `qc` | `mm` |
| `CHANNEL` 请求头 | `qc` | `mm` |
| 本地存储前缀 | `qc.` | `mm.` |
| API host | `https://www.mimiu.chat` | 同左 |

判断方式：`/mimi/i.test(location.host)` → 迷迷，否则巧巧。脚本里 `MODE`、`SK`、`CHANNEL` 全由它派生。**新增同类站点只改这一处 + `@match`。**

### 11.3 传输：NIM v2 关键事实

- appkey `38fb9a8f641c247d5e887f94eba2e6d4`，`apiVersion:"v2"`，`enableV2CloudConversation:true`。
- 实例获取：`模块.getInstance()` —— 有实例时同 appkey 直接返回已存在的那只，**所以拿到的是页面自己在用的对象**，登录态、重连、心跳全都现成。
- 登录（页面做的事，脚本不重复做）：`V2NIMLoginService.login(imId, imToken, {forceMode:true, retryCount:3, authType:0})`，`imId` / `imToken` 来自 `POST /api/user/im/token`。
- 自己的 imId = `"q_" + localStorage['<sk>sid']`（两站都是 `q_` 前缀，源码里是 `` `q_${sid}` ``）。
- 发送：`V2NIMMessageCreator.createCustomMessageWithAttachment({raw}, subType)` → `V2NIMMessageService.sendMessage(msg, conversationInfo.id)`。
- 接收：`V2NIMMessageService.on('onReceiveMessages', list)`。
- 通知：`V2NIMNotificationService.on('onReceiveCustomNotifications', list)` / `sendCustomNotification(convId, JSON.stringify({subType, info}))`。

**全部消息都是 custom message（`messageType === 100`）**，正文在 `attachment.raw` 里，形如 `{"body":"<AES密文>"}`。

### 11.4 加解密（最容易写死的地方）

- 算法：AES-ECB / PKCS7，key 为字符串 `6399717526910958`（CryptoJS `enc.Utf8.parse`）。
- 模块导出 `{ w: 加密, Y: 解密 }`。实测 `w('测试')` → `"gImismYlBE/gp7nlgi6RiQ=="`，且 `Y(w(x)) === x` 往返成立（迷迷站线上验证，2026-11-23）。
- **模块 id 会变**：静态分析里是 `959`，线上实际是 `1959`（分包 id 被改写）。`8242`（SDK 模块）实测稳定，但也不能赌。
- 因此脚本**按源码特征扫描模块**：含 `V2NIMLoginService` 且导出有 `getInstance` → SDK；含 `6399717526910958` 且导出有 `w`/`Y` → AES。扫一次后缓存。

拿 webpack require 的姿势（唯一可靠的一种）：

```js
let req = null;
window.webpackChunkxchat_web.push([[Symbol('arsenal')], {}, (r) => { req = r; }]);
```

> 注意：`bu.js` 环境里 `self` 不可靠，**用 `window`**。

### 11.5 消息 subType 枚举（模块 6260 实测原值）

`text:1, picture:2, video:3, audio:4, dice:5, topic:6, conversation_matched:100, conversation_disconnect:102, ban_status_change:201, inputting:301, revoke_message:302, be_muted:900, be_baned:901, custom_notify:1000`

- `receiveList: [1,2,3,4,5,6,302]`（302 撤回消息也收，脚本里收到 302 直接跳过）。
- `visibleList: [1,2,3,4,5,6]`。

### 11.6 匹配机制（和星缘/nvda 完全不同）

1. `POST /api/match/start`，body：`{gender, age, tags, hideLocation, hideVipTag, openBan, filterGender, filterLocation, filterAge}`。
2. **配对成功不由这个接口返回**。接口只表示"已进入队列"；真正配到人是**服务端推一条自定义通知** `subType 100 conversation_matched`，`content = JSON.stringify({subType:100, info:{conversationInfo, contactInfo}})`。
3. 前端有 **30 秒**超时（`setInterval` 计数，到点弹"匹配超时"）。
4. 断开：`POST /api/match/disconnect`，body `{disconnectId: 自己的imId, notifyId: contactInfo.imId, chatLength}`；同时可选发 `subType 102` 通知对方。
5. 对方离开 → 收到 `subType 102`，`info.disconnectId` = 对方 imId（若是自己发的就忽略）。

**脚本的匹配状态机**：`matchNow()` → 30s 定时器 → 没配到就退避 3–6 秒重试；收到 `100` 立刻 `clearTimeout` 并开聊；收到 `102` 或发送返回 `102426`（被拉黑）→ 标记会话失效 → 退避 1.8–3.8 秒再匹配。

### 11.7 一对一模型带来的设计差异（用户明确要求的）

用户原话："他这个只能没有消息列表。所以后台也不用继续匹配。他是一对一的，离开后再匹配，还是一对一。"

所以本脚本**没有**星缘/nvda 那套多会话池、侧边栏轮询、`maxChats` 调度：

- 同一时刻只有一个 `conversationInfo`，只对 `conversationId === conv.id` 的消息做回复。
- **不做后台持续匹配**：匹配只发生在"当前没会话"时；聊天中绝不调用 `match/start`（否则服务端可能给你换一个人，会话状态会乱）。
- 对方一离开就自动重配（开关可控），配到谁算谁。
- 面板只有一个状态位，不列会话。

### 11.8 服务端"只匹配女生"能不能成？

- `filterGender` 在站点购买弹窗里被列为**会员权益**（"性别筛选"），取值枚举里明文可见的只有 `{value:0,name:"不限"}`，第二个按钮是 `value:2`（分包 `chunks/860.js` 里按钮是 base64 图标 + 文本，**没抓到男女标注**）。
- 所以脚本做了双保险：开"只匹配女生" → 请求带 `filterGender: 2`；同时**客户端兜底**——配对成功后读 `contactInfo.gender`（兼容 `sex`），若等于非 `2` 的值就立刻断开并重配，不浪费话术。
- **未验证项**：非 VIP 账号服务端是否真的按 `filterGender` 过滤（可能被静默忽略）；`2` 是否确定是"女"；`contactInfo` 是否一定带 `gender` 字段（静态代码里没抓到明文取值）。**首次带真号实测时，先看日志里"配对成功：xxx（性别N）"这一行。**

### 11.9 账号与登录（重要限制）

没有注册接口，**不能像星缘那样批量造号**。可用入口只有：

- 手机号 + 短信验证码（**4 位**）：`POST /api/login/send/sms`、`POST /api/login/sms`
- 用户名 + 密码：`POST /api/login/password`（前端会先对密码再哈希一次）
- QQ / 抖音 / 微信 授权

登录态存 `localStorage` 的 `token` / `username` / `sid` / `imToken`（键名带前缀），脚本启动时自己读，**不需要用户再填**。`forceMode:true` 意味着**同号在别处登录会互踢**——后台别同时挂同一个号。

### 11.10 请求封装（跟页面一致）

Content-Type: application/json

响应 `{code:0, content}`；错误码：`40001` 需登录、`40002/40003` 登录过期/异常、`41555`/`41666` 禁言、`102426` 被拉黑、`60777`、`70002`。
常用接口：`match/start`、`match/disconnect`、`user/im/token`、`user/get/info`、`system/tag/list`、`complain/commit`、`customer/auto`（**站点自己的 AI 托管回复，说明服务端能读到明文**）、`bottle/*`、`pay/*`。

### 11.11 话术与安全

- 人设沿用 §2：具体男生、短句口语、不查户口、不固定套话。
- 三档池子：`warm`（寒暄）→ `probe`（试探）→ `deep`（深聊），带"去重袋"防连续重复；**连续两次反问后强制改陈述**，避免像审问。
- 出站清洗：命中 `微信/vx/qq/电话/加我/二维码/https/链接` 一律**丢弃不发送**（不是替换成别的，避免说出更怪的话）。对方问要联系方式 → 回"先聊着呗"那类软推。
- 节流：单条 ≤ 42 字、两条之间 ≥ 2.6 秒、单号每小时 ≤ 40 条；对方连发多条只回一次（`pendingReply` 定时器覆盖）。
- 沉默处理：对方连回两次 1–2 字（"嗯""好"）→ 降级为极简回应；不追。

### 11.12 面板

右下角固定小卡（`#ars-qq-panel`，250px 宽、深色、可点 "–" 收起）：状态行 + `开始/暂停`、`匹配`、`断开` 三个按钮 + 三个开关（只匹配女生 / 自动打招呼 / 离开后自动再匹配）+ 6 行滚动日志。

**实现红线**：只 `append` 自己的节点，不 `MutationObserver`、不扫全页、不 `remove()` 站点元素（§0 第 4 条），因此不会拖卡页面。设置存 `localStorage['arsenal.qq.settings']`，**与站点自己的 `qc.`/`mm.` 键隔离**。

### 11.13 坑位清单

1. **模块 id 会漂**（`959`→`1959`）：永远按源码特征扫描，别写死数字。
2. **`bu.js` 里 `self` 不可靠**：用 `window`。
3. **浏览器探针要一次调用内做完**：`bu.navigate(...)` + `wait_for_load` + `bu.js(probe)` 写在**同一个 cell**；分两次调用会附着到漂移的标签页（曾探到 `httpstatus.io/403` 的残留页，结果 `webpackChunkxchat_web` 取不到）。
4. **页面每次刷新 webpack chunk 数组会重新 push**：脚本只 push 一次并缓存 `req`。
5. **未登录时 `getInstance()` 可能抛出**：`boot()` 里循环 20 次 × 700ms，仍失败就显示"请先登录账号"，不假装就绪。
6. **`match/start` 返回 0 不等于配到人**：必须等 `subType 100` 通知，否则会误判"已匹配"而对着空会话发消息。
7. **`102426` 发送失败 = 被拉黑**：直接当对方离开处理，别重试。
8. **`q_` 前缀**：自己 imId 是 `"q_"+sid`；比较 `senderId` 时用这个，不是裸 `sid`。
9. **`/chat` 会 302 到 `/home`**：`@match` 写成 `https://www.qiaoqiao.chat/*` 全路径，别只写 `/chat`。
10. **`@run-at document-idle`**：太早拿不到 `webpackChunkxchat_web`；脚本内部还有 60 次 × 700ms 的等待兜底。

### 11.14 首次使用步骤

1. 装脚本 → 打开站点 → **先在页面上手动登录**（短信 4 位码 / 账号密码 / 第三方）。
2. 刷新一次，面板状态应显示 `就绪，未开始`，日志出现"SDK 已接管（巧巧|迷迷）"。
3. 打开"只匹配女生"→ 点 `开始`（会自动发一次 `match/start`）。
4. 观察日志：应依次出现"发起匹配" → "配对成功：xxx（性别N）" → "我：哈喽" → 对方消息与回复。
5. 若一直"30 秒没有配到"：检查账号是否 VIP / 是否被限流 / 换时段再试；若配到的不是女生且日志显示性别 ≠ 2，说明服务端 `filterGender` 未生效（见 §11.8）。

### 11.16 为什么坚持"SDK 收发 + DOM 只做展示"

旧版 v6.17 的做法是纯 DOM：找按钮文本（`留步`/`发送`/`重新匹配`/`确定`）→ `forceClick`；读 `.user-info` 判性别；点第 5 个图标离开。它能在真机上跑，但代价是：

- 站点改一次按钮文案就全废（"留步"这种词是运营随手写的）；
- 点头像行第 5 个图标离开属于"猜位置"，一旦布局变就发错按钮；
- 页面频繁 `forceClick` 容易触发站点的防抖/误触。

v1.1 的分工：**一切状态变更走 SDK/接口**（匹配、断开、发消息、收消息），**DOM 只负责"读"**（城市行贴标签、性别文案、开关状态）和"append 自己的 UI"。唯一的 DOM 点击是站内两个开关和超时弹窗的确认按钮，都做了存在性判断和一次性标记。

### 11.17 待校准（需要真号跑一次）

日志里带 `[calib]` 的那行会打印：`imId / gender / auto / vip / city / province / registerTime / matchNumber`。紧接着一行是 `页面性别：女｜contactInfo.gender=2（按数字算：女）`。

- 若两行一致 → 可以把 `filterByNum` 打开，DOM 读不到时也能过滤；
- 若**不一致**（比如 DOM 说女、数字是 1）→ 说明 1/2 不是男女，保持 `filterByNum=false`，只信 DOM；
- `auto` 真为 `true` 的号长什么样（是否昵称带"客服/助手"）也值得记一笔，便于调 `skipBot`。

### 11.18 非 VIP 怎么办：客户端硬筛（v1.2）

**用户实测反馈**：`filterGender` 是 VIP 功能，非 VIP 号在站点里根本点不了"只匹配女生"，我也不能指望服务端替我们筛。

**证据链（三处交叉一致）**

| 来源 | 内容 |
|---|---|
| 站点筛选弹（`chunks/860.js`） | `filterGender` 三个选项：`0=不限`、`2=女生`、`1=男生` |
| `app.47537eed.js` 匹配请求 | `filterGender: (localStorage['matchFilterGender']?.value) \|\| 0` —— 前端只是把弹窗选的值塞进请求，没有任何 VIP 判断；服务端忽略就等于没筛 |
| 用户手机截图（2026-11-23） | 对方卡片写"男生 18-22岁"，同时 `[calib]` 里 `gender:1` → **1=男**，反推 **2=女** |

**v1.2 的做法**

1. **`filterByNum` 默认打开**：`contactInfo.gender === 1` 直接判定男。
2. **判定提前到时序最前**：`conversation_matched` 一到就看 `gender`，是男 → 立刻 `match/disconnect`，**不等页面渲染、不发一个字**。原来那套"等 1.2 秒再判"只在数字缺失时才走。
3. **DOM 复核保留**：数字没有（老号/字段缺失）时，1.2 秒后读 `.user-info` 的"男生/女生"再判一次。
4. **换人限流**：10 分钟窗口内换满 6 次 → 停 60 秒；正常换人间隔 2.6–4.2 秒。理由是站点自己的 `matchNumber.matchSum` 是按次计的，狂换会被限流甚至短封。
5. **`serverFilter` 开关保留**：VIP 号可以继续带 `filterGender:2`，不冲突（服务端先筛一遍，客户端再兜一层）。

**实测（云主机浏览器，非登录态、人造会话）**

| 输入 | 结果 |
|---|---|
| `gender:1`（男） | 日志 `性别=1（男），立刻换人` → `已断开当前会话` → 状态 `已换人`，**未发送任何消息** |
| `gender:2`（女） | 日志 `页面性别：未知｜contactInfo.gender=2` → **不换人**，进入打招呼流程 |

代价要知道：**换人是消耗匹配次数的**。截图里那个号的 `matchAllTimeSum:24`、`matchFemaleSum:3` 就是站点在统计。所以别把限流关掉。

### 11.21 v1.3：去掉服务端筛选 / 拦掉反调试 / 面板收进视口 / 间隔可配

用户反馈四条，逐条对应：

**1）"为什么还筛选啊，直接无法匹配"**

v1.2 虽然把判定挪到了客户端，但**请求里仍然带着 `filterGender: 2`**。站点对非 VIP 的处理不是"忽略"，而是让这次匹配直接失败（服务端干脆不给配）。所以表现就是"一直在筛、根本配不上人"。

v1.3 改法：
- `serverFilter` 默认 **false** → 请求里 `filterGender` 恒为 `0`，跟普通用户手动匹配发的包一模一样；
- `onlyFemale` 默认 **false** → 先让你正常配到人、看到完整流程；
- 想筛再自己勾，勾了之后只走客户端（`contactInfo.gender`，1=男/2=女）。

**2）"点开发者工具会跳 https://httpstatus.io/403"**

不是浏览器问题，是站点写的：`app.47537eed.js` 里

```js
n.e(818).then(n.t.bind(n,2818,23)).then(({default:e})=>{
  e({ onDevtoolOpen(){ location.href="https://httpstatus.io/403" }, interval:250, disableMenu:!0, disableKeydown:!0 })
})
```

`js/818.<hash>.js` 这个分块里**只有 2818 一个模块**，就是 `disable-devtool`：每 250ms 检测一次，一开 DevTools 就把整页跳去那个 403 页面。

v1.3 在 `@run-at document-start` 阶段 hook `Document.prototype.createElement`，遇到 `src` 命中 `js/818.<hash>.js` 就**不设 src**（不发起请求、`onload` 不触发、反调试库永远不初始化，Promise 静默挂着，无副作用）。主包其它分块不受影响。

实测：`createElement('script').src='/js/818.abc123.js'` → 属性为空（被吞）；`/js/928.abc123.js` → 正常写入。

**3）"不知道匹配完是啥样子"**

默认不筛之后，一次正常配对在面板上长这样：

```
状态  聊天中
资料  【北京市｜注册:2026-11-23】
统计  匹配 1 / 女生 1
日志  发起匹配（服务端性别筛：关，不带参数｜客户端筛女生：关）
      等待配对（最长 30 秒）
      配对成功：某某（数字性别 2）
      [calib] {"imId":"q_....","gender":2,...}
      资料：【北京市｜注册:2026-11-23】
      页面性别：女｜contactInfo.gender=2
      我：哈喽
```

页面上同时会出现对方的城市标签和我加的 `【城市｜注册:xxxx】`。看到"配对成功"+"我：哈喽"就说明链路完全通了。

**4）"面板缩小后再点一次，内容在底部看不到"**

原因：面板原本 `right/bottom` 定位，拖动后改成 `left/top`，折叠时高度变小、展开时高度变大，而位置钉在底部 → 多出来的内容跑到视口外。

v1.3 加 `clampPanelToViewport()`：折叠/展开后、拖动结束、窗口 resize 时都按 `getBoundingClientRect()` 把面板整体推回视口内（留 8px 边距；如果面板比视口还高，就顶到 8px 从头显示）。

实测：把面板拖到 `top = innerHeight-70`，折叠一次 → 底边 960（视口 993）；再展开 → 顶 557 / 底 985，内容完整可见。

**5）"匹配间隔时间想自己设"**

面板新增一行 `换人间隔 [3] – [6] 秒`，写进 `arsenal.qq.settings`，改完立即生效：

- 换人后重新匹配、30 秒超时后重试、手动"断开"后的再匹配，**全部走这个区间**（`gapMs()` 取 `rnd(min,max)`）；
- 输入非法（0/负数/空）自动回落到默认 3–6；上限小于下限时按上限=下限处理；
- 配合原有的"10 分钟换 6 次歇 60 秒"刹车，频率可以压得很低。

**另外**：老版本存过 `onlyFemale=true` / `serverFilter=true`，会覆盖新默认值，所以加了版本标记 `arsenal.qq.version`，首次加载 v1.3 时强制把它们清成 false 一次（实测：带旧配置注入后面板勾选框为空、请求不再带 filterGender）。

还加了 `统计 匹配 N / 女生 M` 一行，直接看这号被分到什么池子（对上你截图里 `matchFemaleSum` 那种比例）。

        if (code === 40001) log('提示：账号登录态失效，重新登录');
        return;
      }
      log('等待配对（最长 30 秒）');
      clearTimeout(st.matchTimer);
      st.matchTimer = setTimeout(() => {
        if (st.matching && !convActive()) {
          st.matching = false;
          setStatus('这轮没配到', 'idle');
          log('30 秒没有配到，稍后重试');
          scheduleRematch(gapMs());
        }
      }, 30000);
    }).catch((e) => {
      st.matching = false;
      setStatus('网络异常', 'bad');
      log('匹配请求异常 ' + e.message);
    });
    // 兜底：sid 拿不到时也可以靠通知里的 conversationInfo 建立会话
    if (!sid) log('提示：未读到 sid，仍可继续（只发不收损失）');
  }

  function scheduleRematch(ms) {
    if (!cfg.on || !cfg.autoRematch) return;
    clearTimeout(st.pendingReply);
    setTimeout(() => { if (cfg.on && !convActive()) matchNow(); }, ms == null ? rnd(2000, 4500) : ms);
  }

  function disconnectMine(silent) {
    const c = convInfo();
    const ct = contactInfo();
    const me = myImId();
    if (!c || !c.id) return;
    try {
      if (!silent) sdk.V2NIMNotificationService.sendCustomNotification(c.id, JSON.stringify({ subType: NTF.DISCONNECT, info: { disconnectId: me } }));
    } catch (e) {}
    api('match/disconnect', { disconnectId: me, notifyId: ct.imId, chatLength: st.myMsgs }).catch(() => {});
    const next = Object.assign({}, c, { connect: false, disconnectId: me, disconnectTime: now() });
    store.set('conversationInfo', next);
    log('已断开当前会话');
  }

  /* ============================================================
   * 5. 收发消息
   * ============================================================ */
  function sendText(text) {
    if (!sdk) return false;
    const c = convInfo();
    if (!c || !c.id || c.connect === false) { log('当前没有可发送的会话'); return false; }
    const throttle = checkSendBudget();
    if (throttle) { log(throttle); return false; }
    const body = String(text == null ? '' : text).trim().slice(0, cfg.maxLen);
    const safe = sanitizeOut(body);
    if (!safe) return false;
    const raw = JSON.stringify({ body: encText(safe) });
    let msg = null;
    try {
      msg = sdk.V2NIMMessageCreator.createCustomMessageWithAttachment({ raw }, SUB.TEXT);
    } catch (e) { log('建消息失败 ' + e.message); return false; }
    if (!msg) { log('建消息返回空'); return false; }
    try {
      sdk.V2NIMMessageService.sendMessage(msg, c.id).then(() => {
        st.myMsgs++; st.lastSendAt = now(); st.sentThisHour++;
        log('我：' + safe);
        setStatus('聊天中', 'ok');
      }).catch((err) => {
        const code = err && err.code;
        log('发送失败 ' + (code || (err && err.message) || ''));
        if (code === 102426) { log('已被对方拉黑，重新匹配'); onPeerLeft('拉黑'); }
      });
      return true;
    } catch (e) { log('发送异常 ' + e.message); return false; }
  }

  function checkSendBudget() {
    if (now() - st.hourStart > 3600000) { st.hourStart = now(); st.sentThisHour = 0; }
    if (st.sentThisHour >= cfg.maxPerHour) return '本小时发送已达上限，先歇会儿';
    if (now() - st.lastSendAt < cfg.minGap) return '发送太快，缓一下';
    return '';
  }

  // 出站清洗：不出现联系方式、链接、敏感词
  function sanitizeOut(t) {
    const banned = /(微信|威信|薇信|vx|wx|qq|扣扣|企鹅|电话|手机号|加我|加个好友|二维码|扫码|链接|https?:|www\.|\.com)/i;
    if (banned.test(t)) return '';
    return t.replace(/\s+/g, ' ').trim();
  }

  function onMessages(list) {
    if (!list || !list.length) return;
    const c = convInfo();
    const me = myImId();
    list.slice().reverse().forEach((m) => {
      if (!m || m.messageType !== 100) return;
      if (RECEIVE_SUBS.indexOf(m.subType) < 0) return;
      if (m.subType === SUB.REVOKE) return;
      if (me && m.senderId === me) return;
      if (c && c.id && m.conversationId && m.conversationId !== c.id) return;

      let body = '';
      try {
        const raw = m.attachment && m.attachment.raw;
        const obj = JSON.parse(raw);
        body = decText(obj.body);
      } catch (e) { body = ''; }

      if (!body) {
        if (m.subType === SUB.PICTURE) body = '[图片]';
        else if (m.subType === SUB.AUDIO) body = '[语音]';
        else if (m.subType === SUB.DICE) body = '';
        else if (m.subType === SUB.TOPIC) body = '';
        else return;
      }
      onPeerText(body, m);
    });
  }

  function onNotifications(list) {
    const n = list && list[0];
    if (!n) return;
    let payload = null;
    try { payload = JSON.parse(n.content || '{}'); } catch (e) { return; }
    const sub = payload.subType;
    const info = payload.info || {};

    if (sub === NTF.MATCHED) {
      if (!info.conversationInfo || !info.contactInfo) return;
      store.set('conversationInfo', info.conversationInfo);
      store.set('contactInfo', info.contactInfo);
      st.matching = false;
      clearTimeout(st.matchTimer);
      st.matchedAt = now(); st.stage = 1; st.peerMsgs = 0; st.myMsgs = 0;
      st.greetSent = false; st.coldCount = 0; st.lastHadQuestion = false;
      const ct = info.contactInfo || {};
      st.matches++;
      updateStat();
      setStatus('聊天中', 'ok');
      log('配对成功：' + userId(ct) + '（数字性别 ' + (ct.gender != null ? ct.gender : '?') + '）');
      afterMatched(ct);
      return;
    }

    if (sub === NTF.DISCONNECT) {
      const d = info.disconnectId;
      if (d && d === myImId()) return;  // 自己发的
      onPeerLeft('对方断开');
    }
  }

  // 换人节奏：换太勤会被站点限流，连续换 6 次就歇 60 秒
  const skipStat = { n: 0, since: now() };

  // 配到人之后：先记资料 → 数字性别快速判（1=男，立刻走，不等 DOM）→ DOM 兜底复核
  function afterMatched(ct) {
    try {
      log('[calib] ' + JSON.stringify({
        imId: ct.imId, gender: ct.gender, auto: ct.auto, vip: ct.vip,
        city: ct.city, province: ct.province, registerTime: ct.registerTime, matchNumber: ct.matchNumber,
      }).slice(0, 320));
    } catch (e) {}
    renderMeta(ct);                        // 城市｜注册日期｜机器人
    setTimeout(turnOffPure, 500);          // 清流不关，城市那行看不清

    if (cfg.skipBot && ct.auto === true) { log('机器人（auto=true），换人'); leaveAndRematch(); return; }

    // 关键：非 VIP 服务端不会帮你筛，这里按 contactInfo.gender 立刻筛（1=男）
    const numG = numGender(ct);
    if (cfg.onlyFemale && numG === 'male') { log('性别=1（男），立刻换人，不浪费话术'); leaveAndRematch(); return; }

    // 数字拿不到（或不是男）→ 等页面 .user-info 渲染出来再复核一次
    setTimeout(() => judgePeer(ct), 1200);
  }

  function judgePeer(ct) {
    if (!convActive()) return;
    const domG = genderFromDom();
    log('页面性别：' + genderLabel(domG) + '｜contactInfo.gender=' + (ct.gender != null ? ct.gender : '?'));
    const eff = domG || (cfg.filterByNum ? numGender(ct) : null);

    if (cfg.onlyFemale && eff === 'male') { log('不是女生（DOM 复核），换人'); leaveAndRematch(); return; }
    if (eff === 'female') { st.femaleCount++; updateStat(); }
    if (cfg.onlyFemale && !eff) log('性别没读到，先留着（数字字段也没有，只能等对方开口）');

    if (cfg.greet && !st.greetSent && st.peerMsgs === 0) {
      setTimeout(() => {
        if (!convActive() || st.peerMsgs > 0) return;  // 对方先说话了就不重复打招呼
        if (sendText(pick(['哈喽', '哈喽', '哈喽呀']))) st.greetSent = true;
      }, rnd(900, 1600));
    }
  }

  function leaveAndRematch() {
    clearTimeout(st.pendingReply);
    st.pendingReply = null;
    st.greetSent = true;          // 都要走了，别再说一句
    disconnectMine(false);
    setStatus('已换人', 'busy');
    skipStat.n++;
    if (now() - skipStat.since > 10 * 60 * 1000) { skipStat.n = 1; skipStat.since = now(); }
    if (skipStat.n >= 6) {
      skipStat.n = 0; skipStat.since = now();
      log('连续换人 6 次，停 60 秒再匹配（防站点限流）');
      scheduleRematch(60000);
      return;
    }
    scheduleRematch(gapMs());
  }

  function onPeerLeft(reason) {
    const c = convInfo();
    if (c && c.id) {
      store.set('conversationInfo', Object.assign({}, c, { connect: false, disconnectId: contactInfo().imId || '', disconnectTime: now() }));
    }
    setStatus('已结束', 'idle');
    log(reason + '，稍后重新匹配');
    clearTimeout(st.pendingReply);
    st.pendingReply = null;
    scheduleRematch(gapMs());
  }

  /* ============================================================
   * 6. 人设与回复策略
   *   原则：短句、口语、不查户口、不要联系方式、不 PUA、不重复
   * ============================================================ */
  const bag = new Set();
  function draw(pool) {
    let cands = pool.filter((x) => !bag.has(x));
    if (!cands.length) { pool.forEach((x) => bag.delete(x)); cands = pool.slice(); }
    if (bag.size > 40) bag.clear();
    const s = pick(cands);
    bag.add(s);
    return s;
  }

  const P = {
    greetBack: ['哈喽', '你好呀', '在呢', '嗯 在的', '哈喽哈喽'],
    warm: ['刚下班 有点累', '今天天气还挺舒服的', '你在干嘛呢', '刚吃完饭 在刷手机', '我这边刚忙完一阵'],
    probe: ['你平时都这个点在线啊', '你说话还挺有意思的', '感觉你挺会聊的', '你平时都玩些什么', '听你这么说 有点好奇'],
    deep: ['我最近也挺宅的 懒得出门', '有时候一个人待着还挺舒服', '你这么一说 我倒想起点事', '我属于慢热那种 聊开了话就多', '说实话 我也不是特别会聊天的人'],
    laugh: ['哈哈哈哈', '笑死 你也太逗了', '这个我真没想到', '行 你赢了'],
    shortReply: ['嗯嗯', '哈哈 咋啦', '在呢', '嗯 你说'],
    coldBack: ['嗯', '好', '行'],
    askBack: ['你呢', '你那边怎么样', '换你了 说说你', '你先说'],
    close: ['那就先这样 有空再聊', '行 不打扰你了', '嗯 那先忙你的'],
  };

  function isContactAsk(t) {
    return /(微信|vx|wx|qq|加个|留个|电话|手机号|联系方式|二维码|扫码)/i.test(t);
  }
  function isGreeting(t) {
    return /^(哈喽|哈啰|hello|hi|嗨|你好|在吗|在不在|在嘛|有人吗)/i.test(t.trim());
  }
  function isQuestion(t) {
    return /[?？]\s*$/.test(t) || /(吗|呢|什么|怎么|为什么|哪|多少|几岁|多大|是不是|有没有)/.test(t);
  }
  function isCold(t) {
    const s = t.trim();
    return s.length <= 2 || /^(嗯+|哦+|好+|行+|ok|okay|额+|啊+)$/i.test(s);
  }

  function replyFor(t) {
    const s = String(t || '').trim();
    if (!s) return draw(P.warm);

    if (isContactAsk(s)) {
      // 不换联系方式，也不硬拒，轻巧带过
      return draw(['先聊着呗', '我这人不太爱加人 先聊着', '哈哈 急啥 先聊着', '暂时不加这些 聊得来再说']);
    }
    if (isGreeting(s)) return draw(P.greetBack);
    if (isCold(s)) {
      st.coldCount++;
      if (st.coldCount >= 2) return draw(P.coldBack);
      return draw(P.shortReply);
    }
    st.coldCount = 0;

    if (isQuestion(s)) {
      // 回答 + 反问，但连续两次反问就改成陈述
      const base = draw(st.stage >= 4 ? P.deep : P.warm);
      if (st.lastHadQuestion) { st.lastHadQuestion = false; return base; }
      st.lastHadQuestion = true;
      return base + '，' + draw(P.askBack);
    }
    if (/哈哈|笑死|😂|🤣|搞笑/.test(s)) return draw(P.laugh);

    st.stage = Math.min(4, st.stage + 1);
    if (s.length >= 18) return draw(P.deep);
    return draw(st.stage >= 3 ? P.probe : P.warm);
  }

  function onPeerText(text, msg) {
    const shown = String(text || '').slice(0, 60);
    log('TA：' + (shown || '[非文本]'));
    st.peerMsgs++;
    st.greetSent = true;
    if (!cfg.on) return;
    if (!convActive()) return;
    if (text === '[图片]' || text === '[语音]') {
      scheduleReply(() => sendText(draw(['看不清 你发的是啥', '刚没注意 你说啥', '这边有点卡 看图没加载出来'])));
      return;
    }
    if (!text) return;
    if (st.stage < 2) st.stage = 2;
    scheduleReply(() => sendText(replyFor(text)));
  }

  function scheduleReply(fn) {
    if (st.pendingReply) clearTimeout(st.pendingReply);
    const delay = rnd(1200, 2800);
    st.pendingReply = setTimeout(() => {
      st.pendingReply = null;
      if (!cfg.on || !convActive()) return;
      // 对方连发多条时只回一次（合并）
      fn();
    }, delay);
  }

  function fmtTs(ts) {
    if (!ts) return '';
    const t = String(ts).length === 10 ? Number(ts) * 1000 : Number(ts);
    const d = new Date(t);
    if (isNaN(d.getTime())) return '';
    return d.getFullYear() + '-' + String(d.getMonth() + 1).padStart(2, '0') + '-' + String(d.getDate()).padStart(2, '0');
  }

  // 资料文案：城市｜注册:YYYY-MM-DD｜机器人/VIP
  function metaText(ct) {
    if (!ct) return '';
    const city = ct.city || ct.province || '';
    const reg = ct.registerTime ? '注册:' + fmtTs(ct.registerTime) : '';
    const flag = ct.auto === true ? '机器人' : (ct.vip === true ? 'VIP' : '');
    const parts = [];
    if (city) parts.push(city);
    if (reg) parts.push(reg);
    if (flag) parts.push(flag);
    return parts.length ? '【' + parts.join('｜') + '】' : '';
  }

## 13. 跑久了卡死 / 下次打开变未登录：成因与对策

### 13.1 症状

- 挂几小时后，页面开始掉帧、点击延迟几秒，最后整页白掉（浏览器提示"页面无响应"）。
- 隔一段时间打开站点，面板显示未登录 / token 失效；等十几分钟到一小时，重新登录又能用。

### 13.2 卡的三类原因（按杀伤力排序）

1. **全页文本扫描 × 高频**。叔叔不约旧版（v2.11）每 500ms 跑两次 `document.querySelectorAll('*')`，再对每个元素读 `innerText`。`innerText` 会强制同步布局，一个 1000+ 节点的页面一次就是毫秒级，500ms 一轮 ≈ 每秒 2 次全量重排，浏览器主线程被吃满。这是最典型的元凶。
2. **面板每秒重写**。星缘 v1.8 的 `renderAll()`、缘起 v1.8 的 `render(1000)`、nvda v1.2 的 `render(2000)`，即便内容没变，也会每秒把整块文字和状态重新赋值一遍。叠加滚动、输入框焦点，会持续触发重排，且用户点按钮时容易"点不中"。
3. **存储膨胀 + 每轮全量读写**。
   - `xy_us_sent` / `nm_us_sent` 是"已打招呼的人"表，只增不减；
   - 旧版还有 `xy_us_black` / `nm_us_black` 男号名单，跑一晚能上千条；
   - 每轮 `JSON.parse` 整个表 + 写回，数据越大越慢，且 `localStorage` 是同步 IO，写在主线程，卡顿直接可见。
4. **日志/消息无限累积**。聊天记录、面板日志 DOM 节点只增不减，几百条之后每次插入都在长列表上重排。
5. **站点自身的反调试**。巧巧/迷迷用 `disable-devtool`（250ms 一次检测），配合 5 个脚本同时跑，本身也占一份 CPU。

### 13.3 掉登录的原因（不是封号）

- **风控限流**：短时间内大量"匹配→断开→再匹配"、批量开聊，服务端返回 401/429，前端拿到 401 后会主动清 `localStorage.token`，于是下次打开就是"未登录"。
- **多端并跑互踢**：同一个账号在两台设备/两个浏览器同时在线，后登录的把前一个踢下线，token 失效。星缘脚本里那段 `forceMode`（强制踢掉其他端）就是为此存在的双刃剑。
- **服务端会话过期**：签名 token 有 TTL，长时间不活跃后失效。

**结论**：这类失效是"冷却期"性质，等限流窗口过去、重新登录即可恢复，不是账号被封。真正的封号会连登录接口都拒绝、或登录后立刻掉线，且不会自己恢复。

### 13.4 已做的降载（本轮）

| 动作 | 站点 | 效果 |
|---|---|---|
| 删男号黑名单 + 清历史键 | 星缘、缘起 | 去掉每轮线性扫描，localStorage 体积不再随时间增长 |
| 面板渲染 1s → 2s | 星缘、缘起 | 重排次数减半 |
| `findByText` 限频 + 先扫作用域容器（`.uni-page-body` / `#app`），全页扫最多 2 秒一次 | 叔叔不约 v3.0 | 从每秒 2 次全页 `innerText` 降到每 2 秒 1 次，量级下降 |
| 主循环 500ms → 1.2s | 叔叔不约 v3.0 | 调度开销降低 |

### 13.5 还没做、建议做（等用户拍板）

- **401 冷却**：任一接口返回 401 时，脚本暂停 5–10 分钟，别继续打；并在面板显示"限流冷却中"。这是解决"掉登录"最直接的一条。
- **sent 表裁剪**：只保留最近 500 条 / 7 天，超出丢弃。
- **日志环形缓冲**：面板日志只留最近 30 行。
- **单浏览器只跑一个站**：5 个脚本同时挂在一个 Chrome 里，CPU 是叠加的；建议分浏览器配置（Chrome profile）或至少关掉不用的。
- **换人间隔下限**：低于 2 秒等于自己往风控枪口上撞；脚本已把默认设 3–6 秒。

### 13.6 自查方法

- Chrome 自带任务管理器（Shift+Esc）看该标签页 CPU；脚本一开就飙到 20%+ 基本就是全页扫描或每秒重写。
- 控制台跑 `JSON.stringify(localStorage).length` 看体积，超过 1MB 就该清理。
- `performance.now()` 包住主循环函数，打印单次耗时，>20ms 就要优化。

### 14.6 自动更新（2026-11-23 已补齐）

五个脚本头部都加了这两行，指向 gh-proxy.org 上的 raw：

```
// @updateURL    https://gh-proxy.org/https://raw.githubusercontent.com/BlackJNG/chat-scripts/main/scripts/<文件名>
// @downloadURL  https://gh-proxy.org/https://raw.githubusercontent.com/BlackJNG/chat-scripts/main/scripts/<文件名>
```

- `<文件名>` 用 **percent-encoded** 形式（中文文件名在元数据里不能直接写，油猴按 URL 抓取，编码后等价）。
- 油猴默认每 24 小时检查一次 `@updateURL` 里的 `@version`，发现更高版本就自动下载 `@downloadURL`。
- **ghproxy 有缓存（几分钟）**，刚 push 完立刻检查可能仍是旧版，等 5 分钟或手动点"检查更新"。
- 版本号规则：补这类基础设置算小版本（1.9→1.10、1.2→1.3、3.0.0→3.0.1、1.3.0→1.3.1）。

**注意**：本文件 §12 附录里的源码是 v1.3 那时的**历史快照**，不再逐字同步；以仓库 `scripts/` 下的文件为准。

`push.sh` 在仓库根目录，一次性完成"建仓 → commit → push → 打印安装链接"。需要 `GITHUB_TOKEN`（fine-grained PAT，勾 `repo` / Contents 写权限）。

**仓库地址（待推送）**：`https://github.com/BlackJNG/chat-scripts`

### 14.4 为什么用 gh-proxy

`raw.githubusercontent.com` 在国内经常 443 不通或极慢，`gh-proxy.org` 是稳定可用的反代（实测同一文件 1.4s vs 旧代理 7.7s）。脚本管理器里填 ghproxy 链接，改完 push 后客户端直接 reload 就能拿到新版，不用再走 CDN 手工上传。

**注意**：gh-proxy.org 有缓存（通常几分钟），刚 push 完可能读到旧内容，加个 `?t=时间戳` 或等几分钟。

## 15. 叔叔不约（shushubuyue.net / .com）· v3.0

### 15.1 站点结构侦察结论

| 项 | 结论 |
|---|---|
| 域名 | `https://www.shushubuyue.net/`、`https://www.shushubuyue.com/`（内容同构，同一套前端） |
| 前端 | uni-app H5（`assets/index-BGBACZNn.js`，约 47 万字符），页面壳极薄（13–20KB） |
| 传输 | **自研 WebSocket**，不是 socket.io |
| WSS 地址 | `wss://server08.unclenoway.net:48083`；代码里端口规则 `s.replace(/:(\d+)$/, ':4$1')`（`:8083` → `:48083`） |
| 兜底地址 | 受限用户切 `wss://fallbackserver.shushubuyue.net` |
| 接口基址 | 匹配/聊天 `https://fc.unclenoway.net`；安全/验证 `https://api.shushubuyue.net:43121`；支付 `:43301` |
| 登录 | 依赖腾讯验证码 `TJCaptcha.js` + 短信 SDK `fc.unclenoway.net/account/aliyun-sms/sdk` |
| 风控标记 | bundle 里有 `bottle_user_is_restricted`，受限账号会被切到 fallback 服务器 |

### 15.2 为什么这一版先做 DOM 路径

socket 版必须先登录、再抓一次真实 WSS 帧（握手参数、鉴权字段、消息 opcode、心跳、离开/匹配的信令名）才能实现。没有帧样本硬写等于猜协议，上线必崩。所以本轮交付 **v3.0 DOM 版**：把旧 v2.11 的选择器全部保留，重点修性能和交互，等抓到帧再上 v4 socket 版。

### 15.3 v3.0 做了什么

- **面板**：状态、对方（性别/标签/昵称）、统计（匹配数/换人数）、开始-暂停、单次匹配、断开、三开关（自动打招呼 / 离开后自动再匹配 / 跳过机器人）、可设**换人间隔**（默认 3–6 秒）、最近日志。
- **拖动 + clamp**：面板可拖，拖出视口会自动收回来（沿用巧巧/迷迷 v1.3 的 `clampPanelToViewport`，解决"展开后按钮跑到屏幕外点不到"）。
- **男生秒离开**：读到"对方信息"里是男生，立刻走离开流程（不等间隔、不进冷却）。
- **对方离开兜底**：长条"离开聊天"红按钮（`uni-view` + `bg-red-\d+`）出现即点，确认弹窗 `.uni-modal__btn_primary` 也点，2 秒兜底超时后直接重匹配，防卡死。
- **清流标签跳过**：对方只有"清流"一个标签时，不发消息直接换人。
- **音效**：不再依赖 DOM 猜开关，改为一次性尝试（开菜单 → 读圆点状态 → 需要就点一下 → 关菜单），失败只记日志不影响主流程。
- **性能**：`findByText` 先扫 `.uni-page-body` / `.chat-container` / `#app`，全页扫最多 2 秒一次；主循环 500ms → 1.2s；状态比对用签名（`key = 昵称|标签`）避免重复动作。

### 15.4 与旧 v2.11 的差异

| 项 | v2.11 | v3.0 |
|---|---|---|
| 主循环 | 500ms | 1.2s |
| 全页 `querySelectorAll('*')` | 每轮 2 次（≈每秒 4 次） | 每 2 秒最多 1 次，且先扫局部容器 |
| 男号处理 | 主动离开（受冷却） | 主动离开，不受冷却 |
| 换人间隔 | 写死 | 面板可设 3–6 秒 |
| 面板 | 只有一个悬浮球 | 完整面板 + 统计 + 日志 + 拖动 clamp |
| 音效 | 猜开关 + 监听全 DOM 变化（`MutationObserver` subtree） | 一次性尝试，不监听全树 |

### 15.5 socket 版（v4）怎么做

1. 在已登录的浏览器里抓一帧：打开 DevTools → Network → WS → 选中 `server08.unclenoway.net:48083` → 看 Messages。
2. 记录三件事：**握手 URL 的 query/header**（通常带 token/uid）、**每条消息的 JSON 结构**（`{type, op, data}` 之类）、**心跳周期**（多久发一次 ping）。
3. 对照做匹配/发送/离开三个动作，看服务端返回什么（成功/失败/被挤）。
4. 实现要点：复用页面 handler 至少要能拿到页面自己的 `ws.send`；不能另开一条（可能被判定多端）；离开信令一定要发，否则服务端会话残留。
5. 风险：该站有 `bottle_user_is_restricted` 风控，高频匹配大概率被切 fallback 或直接限流，间隔仍建议 ≥3 秒。
